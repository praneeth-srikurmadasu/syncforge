How failures are handled

Retries. Temporary failures (timeouts, server errors, rate limiting) are retried with exponential backoff and jitter, honouring Retry-After. Errors that retrying cannot fix, such as rejected credentials, are not retried.

Dead-letter queue. When a step's retry budget runs out, or on a non-retryable error, the event stops and is kept with its error for inspection and replay.

Circuit breaker. After repeated failures a connector's circuit opens and calls wait instead of failing; after a pause one trial call decides whether it closes again.

Rate limits. A connector can cap calls per minute; work over the limit waits for the next minute without using an attempt.

The exact limits are backend settings, described in docs/reliability.md.
